# Local Assistant v0.2.0-alpha.1

Public developer alpha, released October 11, 2026 under Apache 2.0.
This release provides a fixed source snapshot for developers and early testers.
It requires a Mac, Swift 6-compatible developer tools, a Messages account and manual
permission setup. It does not provide a notarized app installer or model weights.

## Install

```bash
git clone --branch v0.2.0-alpha.1 --depth 1 https://github.com/pranavdulepet/local-proactive-assistant.git
cd local-proactive-assistant
bash scripts/start.sh
```

Alternatively, download `local-proactive-assistant-v0.2.0-alpha.1.zip` or `.tar.gz` from the
[release page](https://github.com/pranavdulepet/local-proactive-assistant/releases/tag/v0.2.0-alpha.1),
extract it and run `bash scripts/start.sh` in that folder. Download `SHA256SUMS` beside the
archives and verify them before extracting:

```bash
shasum -a 256 -c SHA256SUMS
```

Both archives and `release.json` must be present for all checksum entries to pass.
`release.json` records the exact source commit. Checksums detect changed downloads; they are
not an independent publisher signature. See [installation](../install.md) and
[privacy](../../PRIVACY.md) before connecting sources.

## Included

Messages self-chat with local Mac inference, bounded personal-source tools, evidence citations,
durable conversation/reply state, a supervised native host and opt-in daily commitment reminders.
Optional phone context and on-device phone conversation code are included. The release also
contains fixes for native packaging, indexed source refresh, local Calendar dates, Contacts
startup stalls, and reply wording/model markup. See [CHANGELOG.md](../../CHANGELOG.md).

## Validation and limits

The pre-release runtime passed 253 local Swift tests across 53 suites and all CI jobs,
including two macOS versions, native packaging, phone simulator/device compilation and
simulator smoke tests. The release commit must pass the same CI plus source-archive checks
before publication. Public synthetic Qwen runs exercised the production tool loop; some
unwanted speculative caveats and source-instruction commentary remain.

Actual Mac runs observed Delivered replies, bounded source reads and 4.2-second controlled
backend recovery. [The device report](../device-results-2026-10-06.md) documents later source
authorization failures as well. These results are separate from this release's automated checks.

Known limitations:

- Physical iPhone visibility, receive-to-visible latency, reboot/login recovery and 24-hour
  unattended reliability have not completed acceptance. The Mac must remain logged in,
  awake, online and serving; closing its lid can interrupt replies.
- Ad-hoc app updates can invalidate macOS permission identity. Contacts, Reminders and Photos
  still need fresh successful reads after the final installed update on the test Mac.
- Commitment extraction is narrow; completion is manual. Automatic dependency resolution,
  full retraction/correction behavior and calibrated proactive usefulness remain open.
- The second transport adapter is absent. There is no separate assistant sender identity.
- Phone background context, away-from-home reachability and physical offline-model behavior
  remain unverified. Simulator checks do not establish these behaviors.
- There is no Developer ID signed/notarized download, App Store/TestFlight release or complete
  native first-run setup. Phone builds require your own Xcode signing team.
